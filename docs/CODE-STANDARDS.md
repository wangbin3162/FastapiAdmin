# 验收标准

改动只有在以下每条都「通过」，或对无法执行的条目明确标注「未验证/未跑」并说明原因时，才算完成。
**跑过的检查写明结果；没跑的检查写「未跑」，不许省略。**

## 一、验收标准

### 1. 关键行为有能区分修复前后的检查

为关键行为补回归测试时，把旧代码放回去跑新测试，应出现**真的 `FAIL`** 并点名具体行为；编译错误、跳过、断言缺失不算。高风险逻辑在可安全还原的自有改动上做反向验证（改坏→变红→还原→变绿），不覆盖用户已有改动；做不了就记录原因。

### 2. 用例设计

新增功能至少覆盖：

1. **等价类**：合法/非法/空值/null/格式错误；
2. **边界值**：`min-1/min/min+1/max-1/max/max+1`；
3. **输入域**：类型、长度、枚举、关联字段、状态流转；
4. **正交组合**：角色 × 状态、数据权限 × 状态、协议 × 分片参数等；
5. **接口**：正常路径、非法输入、越权、重复提交、批量部分失败；
6. **UI**：空值校验、成功创建、按钮/弹窗/富文本/下拉等真实交互。

已有资产：`backend/tests/test_input_domain_boundaries.py`（输入域/边界/正交）、`backend/tests/`（服务层、SQL 控制台、SSH、调度器、存储、时区）、`frontend/web/src/__tests__/`（路由/HTTP/冒烟）。覆盖基线与缺口见 [`COVERAGE-PLAN.md`](./COVERAGE-PLAN.md)，改测试状态时同步更新。

### 3. 测试数据与沙箱

- 后端测试默认用临时 SQLite（与开发库隔离，不碰真实数据）；涉及迁移或 PG 特有语义时用 `TEST_DB_TYPE=postgres` + `TEST_DB_*`（默认库 `fastapiadmin_test`，需事先创建）（`backend/tests/conftest.py`）。
- 测试数据统一 `e2e_` 前缀，每次运行生成唯一后缀；由 AI 创建、使用、清理，不依赖用户手工准备。
- 清理：先 API 删除，再按需硬删遗留的软删除行，并清理对象存储桶/对象。
- 不把真实密码、SSH 私钥、第三方 Key 写进测试文件或提交记录。
- 生产 `DEMO_ENABLE=true` 会拦截写操作；测试写接口前先确认环境，别把拦截误判为代码故障。
- 浏览器自动化：隔离的临时 profile；启用 `--use-mock-keychain --disable-sync`（及 basic 凭据存储），不复用日常浏览器/钥匙串；动态表单按**字段名**定位，不写死输入框索引；Element Plus 下拉/富文本优先真实鼠标点击。

### 4. 构建与全量套件

```bash
cd backend && uv run pytest -q && uv run ruff check
cd frontend/web && pnpm test && pnpm ts:check && pnpm build
```

UI 改动另按 [`UI-ENGINEERING-SPEC.md`](./UI-ENGINEERING-SPEC.md) §9 评审清单与 §10 验收命令执行。改了 token 先跑 `node scripts/design-tokens/generate.mjs`。

### 5. 尽可能真实使用

「页面能打开」不等于「功能通过」：写操作必须真实提交并清理测试数据。能对真实环境跑的真跑一次；跑不了的写「未验证」，不建立在它之上。当前真实集成仅 MinIO/S3、AI；FTP/SFTP/OBS/OSS/COS 无测试环境。

### 6. 范围检查

提交前看 diff：有无与目标无关的改动，有就拆开。前端改动后核对 dist 产物特征字符串（见 [`DEV-GUIDE.md`](./DEV-GUIDE.md)「前端产物验证」）。涉及文案时 `zh.json` 与 `en.json` 同步，文档站中英两份同步。

## 二、提交信息

type 用 feat/fix/refactor/chore/docs/test 等（commitlint 约束，`pnpm commit` 交互生成；lint-staged 自动格式化，不绕过 hook）。大改动加 body：

```
<scope>: <用户看到的变化，用行为描述>

为什么：<谁报的 / 什么场景 / 不改会怎样>
改了什么：<行为面与边界；相邻情况保持不变>
跑了什么：<具体命令 + 具体结果数字>
没试过：<明确列出没验证的部分>
```

- 标题用行为描述，不写「重构 X」「优化 Y」。
- 数字要具体：写「`uv run pytest -q` 1240 passed」，不写「测试通过」。
- 「没试过」必填；只改错别字可只有标题。
- PR 提交到 `dev` 分支（见 [`CONTRIBUTING.md`](../CONTRIBUTING.md)）。

## 三、复盘

**校准**：小团队、活跃项目。每次发版前，或每 ~20 个提交复盘一次；一次任务里出现返工（同一处改两次以上）立刻复盘。`LESSONS.md` 上限 ≤ 5 条，计数命令见该文件头部。

用独立会话读最近 N 个提交的信息与 diff，回答：

1. 哪些「修完又坏」「改完又改」，根因是什么？
2. 哪些改动不该合进来（夹带、超范围、没验证）？
3. 哪些验证太薄？

每个发现写成一条错题追加到 `LESSONS.md`（规则→症状→根因→证据），已有的复发次数 +1；只报有证据的发现，没有就明说没有。无独立上下文时只报 `git log`/`git show` 可机械核对的事实，并注明是自审。

### 毕业规则

一条错题被**独立踩到 3 次**（分开的时间点；同一任务内犯两回算一次）→ 正文写进下面「已毕业的规矩」，从 `LESSONS.md` 删正文、留一行指针。
